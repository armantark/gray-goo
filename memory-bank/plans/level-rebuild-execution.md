## Runtime interface

Each scene script extends RefCounted. It implements `definition() -> Dictionary`, `ground_height(point: Vector3) -> float`, `build(world: GameWorld) -> void`, and `step(delta: float) -> void`. It stores the passed world when needed. Root constructs it, reads definition, builds terrain/background lighting and walls, then calls build. Root calls step during physics. Keep any scene-specific animation or composition rules in that scene.

Definition keys: title, meters_per_unit, initial_radius, goal_radius, start_position:Vector3, accent:Color, field:Rect2, tiers:Array[String] of five display names, jumps:Array[Dictionary]. Jumps has five entries: entry0 is initial radius/view_size; entries1–4 cause the four transitions. Each entry requires radius and view_size and can set meters_per_unit when physical calibration changes. Optional background_color, key_color, fill_color, ground_color, ground_texture (model texture resource path), visible_ground (bool, defaulttrue). No jump_radius or camera_sizes. All radii increase strictly. Give enough visible space for the largest structure and beyond-wall scenery.

World has current_tier:int=0, foods:Array[Food], pools:Array[LocalPool], player_radius:float, field:Rect2, config:Dictionary, _rng:RandomNumberGenerator, and _time:float. `advance_scale(tier:int)` selects a tier without granting growth. Every whole is visible from the start. All food remains active until consumed, with tier controlling edibility through `world.is_edible(food, radius)`; do not hide future wholes. Old tiny details can be hidden for performance without losing their remaining volume. Scene step can respond to world.current_tier.

Use existing `world._add_food(kind:String, at:Vector2, size:float, threshold:float, volume:float, label:String, moving:bool=false, tier:int=0, parent:Food=null, lift:float=0.0) -> Food`. Coordinates are world XZ for roots, local XZ for parts. Y uses terrain plus lift for roots, local lift for parts. A nonempty kind loads Art.model(kind,size). Empty kind creates a composite with no baked visual and no aggregate collider; its parts form its visible geometry. Root supports this path. Supply a whole's bounds through size and optional `food.height`; never render both baked parts and separate edible copies. Empty-kind composites can have zero own volume. Total remaining volume includes surviving parts recursively. Edibility requires active plus tier<=current_tier plus threshold<=goo radius; separate thresholds remain fixed when parts vanish. Do not allocate excessive RigidBody nodes for distant microdetail; request a root seam if needed.

Food exposes existing parts, parent_food, visual, pigment, radius, height, threshold, volume, model_name, active, freeze, drift, linear_velocity. Root adds `part_consumed(part:Food)` signal on the immediate parent after a child becomes consumed and `rename(label:String, color:Color)` for label/pigment/visual tint changes. Root adds `context_whole:Node3D` and `loose_reason:String` for scene membership verification where a structural parent is unsuitable (plankton/current, litter/gutter, stellar filament). Set at least parent_food or context_whole on every food; loose food also needs its causal reason. A context whole must have visible geometry, not be an invisible label-only node. Root adds `touch()` signal callback support for anemones when goo contacts them. Do not invent damage or penalties.

World `_pool(at:Vector3, extent:Vector2, color:Color, volume:float, threshold:float=0.0, fabric:bool=false) -> LocalPool` returns the pool.
